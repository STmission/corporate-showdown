# 11 · Riot 公开实践参考与项目制作基线

版本 v0.1 · 2026-10-02 · 全项目生效的制作方向；实施与验收尚待逐项完成

## 1. 决策与适用范围

用户授权游戏代码、文档、玩法及场景设计改用 Riot Games 公开实践作为参考。范围涵盖客户端、联机服务、策划配置、3D 资产、音频、测试、平台适配和发行文档。此前以腾讯公开工具为主要工程参考的说明由本基线替代；微信平台要求照常适用。

公开实践与本项目规则分别记录。来源见 [07 · 公开参考](07-public-references.md)。未获得 Riot 内部规范；采用本基线不会自动产生公司认证、发行资格或成熟产品品质。

保留用户明确需求：准时下班的职场主题、第一人称视角、多人场景闯关、NPC 与 BOSS 战斗、男女与职务换装、海景办公楼，以及微信小游戏 / iOS App 目标。已确认的办公区域布局继续作为设计基础。调整须说明玩家体验问题、设计理由、兼容影响与验证结果。

## 2. 玩法制作规则

- R-GDD-001 MUST：普通战斗、技能和 BOSS 大招都有可识别的准备、效果与结束信息。危险招式有可执行的躲避、打断、掩体或队友配合方式；预警时长通过触控与网络条件试玩确定。
- R-GDD-002 MUST：职业有明确的优势、限制和合作用途。研发偏干扰，销售偏牵制，电商偏补给，明星偏机动；这里只是角色职责提案，数值和技能在可玩切片验证后冻结。性别 / 服装不改变命中范围、移动速度或伤害。
- R-GDD-003 MUST：保留“交接任务—选择路线—应对阻拦—打败 BOSS—撤离”的核心循环。倒计时制造选择压力，任务状态和退出入口始终可理解。
- R-GDD-004 MUST：多人共享任务进度，救援有明确反馈，断线与主动退出有确定处理。主线机关不能要求唯一收费角色或未到场的特定队员。
- R-GDD-005 MUST：PvP 使用同一竞技参数与明确匹配规则。PvE 付费英雄保持横向玩法区别和免费通关路径；付费工具实验继续遵循 02 文档的局外、非竞技限制。正式支付另行验收。
- R-GDD-006 SHOULD：普通模式先验证单人 / 双人 / 四人首关闭环，再制作独立竞技模式。内容扩展以不同招式、空间和合作选择为核心。

## 3. 场景与美术规则

- R-ART-001 MUST：敌人、队友、危险区域、可交互物、出口与纯装饰有稳定识别语言。不能只依赖颜色；需要轮廓、图标、动作或音频辅助。
- R-ART-002 MUST：保留海景、工位、茶水间、演讲区、中央休息区、玻璃会谈室和卫浴布局。对玻璃反射、强日光、植物及家具密度的调整，以是否挡住关键视线和路径为依据。
- R-ART-003 MUST：战斗区的视觉掩体与服务器碰撞对应；雕塑、猫玩具、餐具等装饰不自动成为战斗阻挡。每条玩家路径需要清楚入口、目的地和通行宽度。
- R-ART-004 MUST：环境、人、服装、骨骼、动画、碰撞、导航、光照、特效和音频分开管理，源文件可追踪到导出版本。导出检查比例、轴向、贴图、透明模式、骨骼和动画。
- R-ART-005 SHOULD：办公室人物采用原创东亚职场造型、适度写实的比例和材质。脸部、服装褶皱、发型和远景细节按镜头距离分级，避免近景预算应用于全部背景人物。
- R-ART-006 MUST：急促下班节拍和广播不能掩盖敌人预警、交互反馈；提供独立音量控制，并检验触控、眩晕与字幕体验。

## 4. 代码、联机与工程规则

- R-TECH-001 MUST：服务器裁决移动约束、伤害、技能冷却、AI、任务、计时、库存与结果。客户端发送输入与意图；预测仅改变本地表现。
- R-TECH-002 MUST：采用固定模拟更新，明确输入确认、快照插值、状态纠正和重连规则；记录命中反馈与服务器裁决发生分歧的原因。
- R-TECH-003 MUST：模拟频率、画面帧率和网络预算由本游戏实测决定。当前原型 30 Hz 模拟 / 15 Hz 快照仅是已实现起点，不能因为参考 VALORANT 就直接采用 128 Hz。
- R-TECH-004 MUST：领域规则、表现、传输、持久化和平台 SDK 分层；规则和数值配置可校验、可版本化。先确定正式引擎，避免无依据同时重写多个客户端。
- R-TECH-005 MUST：需求、实现、检查结果与已知差距互相可追踪。CI 执行对应语言的构建 / 语法 / 类型 / 格式 / 静态检查以及必要规则与集成测试；修复不得仅靠屏蔽错误。
- R-TECH-006 SHOULD：先用代码清晰度和模块职责解决问题；不为了“大厂”字样引入未需要的微服务、复杂框架或内核级反作弊。
- R-TECH-007 MUST：协议、资源清单、账户及商品权益有明确版本、身份验证、幂等与失败恢复；日志不记录凭据。

## 5. 验证与发布门禁

以下为本项目的验证方法，不是 Riot 公布的固定阈值：

- R-QA-001：每个核心系统包含正常、边界、非法输入、断线与重复请求案例。沿用当前规则测试，补充真实客户端与服务端集成验证。
- R-QA-002：弱网覆盖约 100 / 200 ms RTT、约 20 ms 抖动、短暂中断与 30 秒断线重连。记录工具、实际网络值与结果；底层丢包用网络整形验证，不能把随机丢弃业务消息当作 TCP 丢包测试。
- R-QA-003：指定最低、主流及高档真机后，记录帧时间 P50/P95/P99、内存峰值、加载、温升、带宽和服务器 tick 尾部耗时。30 / 60 FPS 分档仍是目标，未测量不能写“已达标”。
- R-QA-004：容量测试按真实房间人数、AI 数量及场景复杂度逐步加压；明确瓶颈和容量上限，再确定上线规模。
- R-QA-005：发行前验收平台构建、签名、隐私、账号、存档、支付校验与恢复、资源回退、可观测性和故障处置。微信与 Apple 要求以当时官方资料为准。

## 6. 后续长期任务实施大纲

以下为待启动的工作清单，阶段顺序不构成日期或自动运行承诺。现有 G1/G2 评审编号保持可追踪，M 编号用于长期任务工作包。

### M0 · 差距审查与基线冻结

核对现有玩法源码、文档、GLB、Blender 工程与真实完成状态，建立需求追踪和缺陷列表。交付架构决策、源资产 / 导出资产清单和优先级。退出条件：每个声明有证据，主要依赖与风险明确。

### M1 · 办公楼可玩垂直切片

把已确认的整层场景接入玩法；制作碰撞、导航、任务、敌人预警、BOSS 与撤离路径；补齐第一人称手部以及移动、攻击、受击动画。开展单人 / 双人 / 四人试玩。退出条件：可从大厅进入、完成任务与战斗、撤离或失败、退出并再次进入。

### M2 · 联机质量与代码补齐

实现并验证预测、插值、纠正、输入确认、重连与版本同步，完善模块边界、配置校验、日志、集成测试和 CI。退出条件：既有测试通过，弱网关键流程有记录，重要状态不会重复结算或失去控制。

### M3 · 正式引擎与双端适配

完成 G1 的微信小游戏 / iOS 真机技术验证，选定一条正式客户端路线及精确版本。完成资源分包、触控、生命周期和性能分档。退出条件：两端同一首关可玩且测量结果有设备依据。浏览器原型不算 iOS 或微信正式包。

### M4 · 美术、音频与内容生产

按审核后的角色职责扩展技能、关卡与 NPC；精修人物、家具、猫、材质、动画和音效，建立 LOD 与资源预算。退出条件：每项新增内容通过玩法可读性、资源导出和实际设备检查。

### M5 · 账户、发行服务与商品

完成鉴权、持久化、权益、订单验证、对账、恢复购买与后台运维；建立独立测试环境。具体商品和地区平台能力核验后再接入真实支付。退出条件：存档与交易故障恢复有证据。

### M6 · 回归与发布候选

完成完整功能回归、多人容量、真机兼容、发布文件和提审材料；维护缺陷与发布风险。需要开发者账户、证书、平台审核或人类操作的环节单独记录。验收通过才形成发行候选；“代码写完”不等于“已经上架”。

## 7. 长期任务的建议目标文本

完成 Corporate Showdown《准时下班》的可发布游戏工程与文档：依据本项目 Riot 公开实践参考基线，完善第一人称多人办公楼闯关、职业角色、BOSS、场景与音频、权威联机和双端适配；落实账户存档、资源管理、必要测试、性能验证和发行文档。按 M0—M6 推进，每阶段保存可运行产物、验证证据和真实差距，避免将原型、计划或未执行检查写成已完成。平台发布所需的账户、证书及审核依赖如实记录。

2026-10-02 用户以“按这个来开始吧”正式启动长期目标，已按上述范围建立持续目标。执行状态、差距与验证记录见 [12 · 制作审查](12-production-audit.md)。未创建周期调度，M0 首轮完成，M1 推进中。

## 2026-10-05 用户方向修订

当前出品改为单人剧情，第一／第三人称切换，职业 NPC 交流、线索和分支解压剧情，并要求枪械和近战拾取、人物与场景模块资产。当前单人范围替代旧多人优先次序，底层历史多人回归保留；最新需求、状态与剩余验收见 [29 文档](29-single-player-story-revision.md)。其余工程与质量原则继续适用。
