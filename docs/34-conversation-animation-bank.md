# 34 · NPC 交流动作与独立动画库

2026-10-05 · 根网页 0.6.4 · 动作库 conversation-v0.1 · Cocos 仍为 0.3.1

## 问题与制作决定

六位职业 NPC 已有服务器日常行为与对话，但进入交流后只有站立动作，人物反馈生硬。本轮制作讲解、倾听、安抚三种循环手势，并提取成独立动作资产，继续保留确认后的办公楼、单人剧情、角色性别／装扮和旧多人底层回归。

讲解用于老师、律师与财务；医生采用安抚，教官与诗人采用倾听。这里是通用手势表现，不是完整职业演出或自由语言智能。对话、线索、治疗和角色转向仍由服务器裁决；客户端只根据已确认的 `conversing` 状态选择动作。受击、攻击、倒地和技能优先于交谈，结束交流后自动恢复移动或站立。

## 资产与实现

`assets/animations/conversation-v1/workplace-conversation.blend` 从独立医生工程制作，包含预览角色与三动作；实际 GLB 仅含骨骼与动画，53 骨骼、三段各 4 秒循环，约 104 KiB，无网格／贴图。原医生源与旧八套角色均未覆盖。源码、来源与导出指纹见该目录 manifest，制作与验证脚本位于 blender。

`prototype/public/conversation-animation.mjs` 用来源静止姿态与目标静止姿态转移旋转，不套用女性骨骼的位移／缩放到男性角色。绑定到目标自身骨骼 UUID，避免不同角色的同名骨骼相互影响。现有九套骨骼才是已验证范围；未知骨骼不自动适配。工作台对兼容骨骼提供站立／讲解／倾听／安抚预览，其他自导入模型仍可播放自身动作。

旧八动作合同和 characterRevision 保持不变，Talk 是网页可选补充；原人物 GLB 仍是八动作。网页进入前等待独立动作库，避免先创建的 NPC 缺少交谈动作。根服务增加明确的动画 GLB 和脚本白名单路由，没有任意文件接口。

公共动作选择函数新增默认关闭的 `talkAvailable` 参数，保持旧消费者返回原动作。Cocos 当前仍使用上一版 canonical 选择逻辑与资产，未启用 Talk，未生成本轮引擎包；后续同步与引擎资源接入需要重新构建及验收。协议 3、规则 0.6.1、布局 v0.8 没有变化。

## 已执行验证

- Blender 实际重开源工程，三动作各 5 个姿势采样；实际导入 GLB 保留 53 骨骼与三 NLA 片段。初次验证错误预期导入成 Empty 节点，检查发现 Blender 实际识别为 Armature，已按实际骨骼和片段验证；未忽略角色节点。
- 实际 Three GLTFLoader 读取动画 GLB，核对三片段、4 秒时长、有限数据和闭合循环；对现有八套男女／职务和女医生共九套实际 GLB 的骨骼层级分别重定向三手势，检查头部确有动作、局部位移不变、脚底不漂移和缺骨骼拒绝。
- 浏览器实际进入单人办公室，与许老师交流，动作状态为 Talk／conversing；对白获得日程线索，结束后为 Idle／非交谈，退出后回到大厅。证据 `artifacts/npc-conversation-browser.png` 和 JSON。
- 工作台实际查看女医生安抚、男程序员讲解和倾听；GLB 渲染与所选动作证据见 `conversation-doctor-studio.png`、`conversation-male-studio.png` 和 `conversation-studio-browser.json`。
- `npm run check` 与完整 90 项 `npm test` 通过，日志 `artifacts/conversation-check.log`、`conversation-regression.log`；两个 Blender 脚本另作 Python 语法检查。

## 未完成与后续验收

这是手工关键帧通用手势，仍缺细致手指、职业道具、坐姿、说话口型、表情、视线与语音同步；不能称为真人演出完成。医生服装、其余职业造型、持枪姿态和故事内容仍按 29—33 文档继续。Cocos 动作资源接入、微信／iOS 真机、最终美术、性能与发行未验收。当前网页对白面板遮挡部分 NPC，交流镜头与面板布局还需要改善。
