# 25 · 重复家具 GPU 实例化

版本 v0.1 · 2026-10-04 · 负责人/评审人待分配

## 原因和实现

24 文档的静态合批减少绘制调用，但复制顶点造成约 40 MiB 额外缓冲区。原办公楼 glTF 有 386 个网格，6,300 个引用中 5,976 个引用重复网格，因此试用 GPU 实例化共享原网格，保留逐物体剔除粒度。

`EnvironmentInstancing.ts` 按同一个标准不透明材质和网格分组，仅处理重复组。复制材质并覆盖 `USE_INSTANCING`，保留原属性、贴图、技术和管线状态；不复制或变换几何，不重挂节点，不隐藏原渲染器，不修改布局/碰撞/协议。透明、形变、动态、烘焙/探针、镜像、奇异或剪切变换跳过。失败恢复来源材质；销毁时恢复全部材质并释放变体。

依据本机 Cocos 3.8.8 `material.ts` 的 copy/defines 合并、`pass.ts` 的 INSTANCED_ARRAYS 能力门禁、`rendering/instanced-buffer.ts` 的共享索引缓冲区匹配和 `world-transform.chunk` 的非均匀缩放法线处理。实际能力不支持时保留原渲染，不推断所有真机兼容。

实际内置浏览器 `?batch=instance&profile=on` 中，实例化启用 5,898 个来源、61 个重复网格组、26 个材质变体，失败 0，处理 361 ms。相同大厅视角三角形 322,567，与未优化基线一致；绘制调用 213，缓冲区 30.95 MiB，贴图 161.67 MiB。对比未优化的 2,108 / 28.2 MiB 和静态合批的 856 / 67.85 MiB，此方案明显减少绘制调用和额外缓冲区。

## 对照与开发路线决定

同一个测试页切回静态合批、短暂显示浏览器后复查，静态仍约 2 FPS，绘制 856 / 缓冲区 67.85 MiB；再切回实例化约 2 FPS、绘制 213 / 30.95 MiB。文档可见状态为 visible，浏览器呈现状态也单独检查；低帧率原因仍未定位，不能简单归因于后台或实例化。静态这一轮处理 14,240 ms，比上一轮 1,554 ms 明显更慢，说明计时受当前环境影响，仍需固定设备/条件的正式基准。

选择实例化作为 0.2.2 开发默认，理由是原剔除粒度、原几何保留和新增缓冲区更少；不声称帧率提升。`batch=static` 保留静态对照，`batch=off` 保留原渲染。无参数 Web 和原生平台走同一默认。设备不支持时保留原渲染，不隐藏场景。
