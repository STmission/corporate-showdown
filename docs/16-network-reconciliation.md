# 16 · ADR-004：联机版本、输入确认和移动纠正

v0.4.0 · 2026-10-03 · 浏览器原型已实施并通过规则/真实本地 WebSocket 测试；M2 继续推进。负责人和评审人待团队分配。

依据 11 文档的项目制作基线，参考 Riot 公开实践，不代表其内部规范。

## 问题、决定与兼容

此前快照的 `sequence` 只表示最近收到的输入，无法证明它已参与模拟。客户端完全跟随服务器快照，没有本地移动预测；旧客户端还能直接创建房间，协议差异只在资源准备时暴露。

增加独立协议版本 `protocolVersion=1` 和规则版本 `rulesVersion=rules-0.4.0`。客户端连接后先发 `hello`，服务端核验两项版本并返回场景版本和更新频率；协商通过才开放创建/加入按钮。所有客户端消息和服务端消息包含版本。握手前的创建被拒绝，版本错误不改变房间、玩家或令牌状态。客户端发现不兼容会停止自动重连并提示刷新。

这是破坏性协议迁移：不接受缺失版本字段的旧脚本和旧页面。必须刷新客户端并更新自动化工具；旧连接不提供静默降级。仍采用 JSON/WebSocket 本地传输，没有宣称完成二进制协议、正式账户鉴权或公网部署。

`sequence` 继续表示服务端最后接受的输入，新增 `appliedSequence` 表示固定模拟步骤已经处理的最新输入。两者只在步骤推进时同步。输入仍是持续按键状态，多个在同一步前收到的输入以最新合法状态替换，不是逐命令执行的动作队列；重复、非法和跳跃过大的序号不被接受，服务器不使用客户端报告的伤害、坐标或时间。

## 预测、插值与恢复

模拟 30 Hz、快照 15 Hz 保持不变。客户端输入从 20 Hz 调为 30 Hz，使预测步长与模拟步长一致；现有限速 80 消息/秒仍生效，后续容量测试后再定预算。这不是照搬其他游戏更新率。

`shared/movement.mjs` 提供服务器与客户端共用的移动速度和地面约束。`public/network-state.mjs` 在输入采样时预测平面位移；收到快照后以服务器位置重建，丢弃不大于 `appliedSequence` 的输入，并重放剩余移动输入。预测不产生攻击、技能、交接、拾取、伤害、奖励或通关；变身、咖啡、闪避等状态变化仍依据服务器快照。首次闪避的离散冲步因此由服务器确认后纠正，尚未做完整动作预测。

未确认输入最多预测约 0.5 秒；超出后停止预测，回到最近权威位置，等待新快照。断线清空输入与预测积压，恢复连接必须重新握手；重连使用服务端快照、已收序号和模拟确认序号，旧移动不重放。离开房间清空插值与预测缓存。倒地、撤离等状态优先取权威结果，预测不会恢复生命或操作权限。

队友和 NPC 以约两次快照的延迟缓冲插值位置，不向最新快照之外外推；跨房间、状态变化和显著传送重置或跳过插值，插值点落入碰撞则采用当前权威位置。血量、危险圈、技能施放和任务反馈仍用最新权威信息。相机对小纠正平滑跟随，大位移或碰撞风险直接回到预测/权威位置；进入行动时立即定位到玩家，避免从大厅近览镜头穿过家具。

这是原型移动补偿方案。网络时序不一致、服务器连续持有输入及已确认状态的变化仍会产生纠正；尚未实现客户端采样 tick 的精确时间映射、完整动作预测、回滚命中或可靠业务事件重放。

## 导航查询优化

完整并发回归初次出现联机服务启动超时，单独联机测试通过。导航预计算重复调用遍历 276 矩形的查询，加重并发进程开销。增加 4 米空间桶，按最大 1 米查询半径扩展索引；更大半径保留全量扫描。精确窄阶段仍使用同一矩形规则，不改变门洞或家具碰撞。

新增测试在整层半米采样网格上比较索引与全量查询，覆盖 .05/.36/.4/1/1.25 米半径和桶边界，全部一致。负数与非有限半径被拒绝。优化后完整回归通过，未增加或屏蔽超时条件。单次本地 10,033 次查询测得索引约 64 ms、全量约 592 ms；此记录只证明该进程中的查询开销，不能推导手机帧率或服务器容量。

## 验证证据和剩余工作

`npm run check` 通过；`npm test` 44 项全部通过，保留单/双/四人首关及真实四人房间测试。新增覆盖：

- 握手前拒绝创建、版本不匹配不产生房间、合法握手后正常创建。
- 收到输入与模拟确认的区别、重复输入拒绝、预测即时位移、未确认输入重放、停止后归位。
- 家具碰撞、倒地权威状态、过期快照、预测上限、断线清理与重连重建。
- 队友/NPC 快照缓冲、禁止外推、状态与房间切换。
- 真实本地 WebSocket 两组消息延迟和抖动下的移动、停止、确认与恢复。

最后一轮延迟测试配置 100/200 ms 往返延迟，单向消息延迟叠加 -10/0/+10 ms 周期抖动；握手实际测得约 126/212 ms。最大单次位置纠正约 .31/.46 米；停止后的待确认预测为零，位置与服务器一致，重连身份及确认序号保留。先前单独运行测得约 .15 米纠正，完整并发运行结果有所变化，不能以单次最佳结果作为品质上限。

报告位于本地 `artifacts/network-delay-report.json`，测试重新运行会刷新数字。方法是对真实 WebSocket 的业务消息添加发送和接收延迟，不是 TCP 层丢包整形；未验证 R-QA-002 的全部网络条件，尤其底层丢包、30 秒真实中断和公网路径。

本轮 `browser-use < prototype/tools/browser-smoke.py` 在读取 `document.readyState` 时控制连接超时，未完成新版本网页点击/镜头验收。源码与联机测试通过不能替代此项，也不替代微信/iOS 真机验收。角色切换测试脚本已适配新协议，但本轮未重新完成八套角色的浏览器循环。

M2 仍需可靠事件/请求幂等、长断线与弱网记录、容量/可观测性和 CI；M1 正式移动/战斗/第一人称动画、M3 双端工程与后续账户/发行工作继续保留。
