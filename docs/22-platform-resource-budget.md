# 22 · 平台资源预算与无损构建处理

版本 0.1 · 2026-10-04 · 预算优化推进中，移动性能与发行预算尚未验收

## 依据和范围

延续 21 文档的 Cocos 0.2.0 客户端及共享玩法，不改变海岸总部布局、人物服装、骨骼、动作、碰撞或联网协议。原始 Blender / GLB 继续保留。依据项目基线 R-ART-004、R-TECH-003、R-QA-003，先测量实际资源，避免直接套用其他游戏预算。

生成的 Web debug resources 原盘点：PNG 108.87 MiB、BIN 31.33 MiB、JSON 3.70 MiB。108 份 PNG 中只有 52 种完整字节内容，重复部分约 60.69 MiB。这只反映生成目录，未测量手机下载、显存、峰值内存或帧时间。动态加载所需角色并不自动消除生成包内重复资源。

## 已实施的构建处理

`platform/cocos/tools/optimize_png.py` 在编辑器成功构建后处理生成目录中的 PNG：核验签名、块长度、CRC 与连续 IDAT，解压并重压相同扫描行；颜色、透明度、调色板及其他元数据块按原始字节保留。只在输出更小时替换生成文件，不修改源 GLB、几何、动画、材质 JSON、资源 UUID 或路径。相同输入复用验证结果。

部分环境 PNG 来自 GLB，IEND 后附有 1—3 个零字节。处理器明确验证并保留这部分对齐数据，拒绝任意尾随数据。动画 PNG 跳过，损坏文件报错；构建报告记录处理失败，不把编辑器成功码等同整个流水线成功。

此步骤仅减少文件传输/存储字节，保持原纹理像素与尺寸，不降低 GPU 纹理内存。单个大贴图实验从 5,531,728 字节降为约 4,506,357 字节；这不是整包效果或设备性能验收。

新增自动化覆盖有效含透明度图像、色彩块保持、CRC/截断/非法尾数据/Deflate 损坏拒绝、GLB 对齐尾数据、重复资产路径及非图片文件不变。构建报告记录各 PNG 的前后大小、文件 SHA-256、扫描行 SHA-256 和元数据 SHA-256。最终结果以对应 artifact 为准。

## 后续资源路线和验证要求

- 重复图片应进一步在导入和资源依赖层共享；当前无损处理不消除不同 UUID 的重复文件。
- 将办公楼与人物入口拆为明确 Bundle，建立按房间所需外观的加载、失败重试及资源释放；远程 Bundle 的 CDN、TLS、域名和版本回退另行验收。
- GPU 压缩采用适配平台的格式与通用回退，保持皮肤、法线、睫毛透明度和衣服识别。需验证真机支持、纹理质量和内存，不能仅配置 ASTC 就称达标。
- 人物贴图尺寸、几何/动作 LOD 与室内批处理需要镜头距离及实际设备测量后确定；保留源资产与每个衍生版本关联。
- 保留首次并发回归失败证据 `artifacts/platform-resource-regression.log`：61 项中四项在服务器启动阶段超时。此前 60 项通过仍是历史记录；新流水线完整回归需要避开构建负载复测，不能先写全部通过。

依据：[Cocos 3.8 纹理压缩](https://docs.cocos.com/creator/3.8/manual/en/asset/compress-texture.html)说明平台格式及通用回退；[Asset Bundle](https://docs.cocos.com/creator/3.8/manual/en/asset/bundle.html)说明依赖、优先级、远程和分包配置。官方机制不是本项目设备验收结果。

为避免资产解析、多个服务启动及构建并发争用同一机器，根目录 `npm test` 调整为按测试文件顺序执行。保持原启动/消息超时、断线时长和断言不变；不是提高等待阈值来掩盖失败，也不是服务器容量测量。首次失败日志保留，复测结果另存 `artifacts/platform-resource-serial-regression.log`。

独立验证工具 `verify_png.py` 使用已有 Pillow 解码优化文件和 Cocos library 原图片，比较模式、尺寸、逐字节像素及图像元数据；它不参与生产压缩，压缩本身仅依赖 Python 标准库。渲染、显存和真机门禁继续单独验收。

压缩级别采用 zlib level 6。对一份实际大 PNG 的前 2 MiB 扫描行测量，level 6 约 0.32 s / 410,954 bytes，level 9 约 4.23 s / 381,196 bytes。level 9 的整包处理已主动终止（仅涉及可重建生成文件），改用 level 6 后要求重新构建。证据 `artifacts/png-level-benchmark.json` 与 `artifacts/png-level9-cancelled.json`；这不是全资源压缩耗时或设备下载指标。

## 本轮实际结果

- Web 与微信构建的编辑器成功码均为 36，无损处理也通过；报告中的工具指纹与当前源码一致。
- Web 的 108 份 PNG：108.87 → 107.18 MiB；微信：108.89 → 107.20 MiB。减少约 1.69 MiB，收益有限，仍需共享贴图、分包和 GPU 预算，不构成移动包体验收。
- 独立 Pillow 验证分别解码 108 份 Web / 微信资源，与 Cocos library 导入原图比较像素、模式、尺寸及图像元数据，均一致。报告为 `artifacts/cocos-web-decoded-png-verification.json` 和 `artifacts/cocos-wechat-decoded-png-verification.json`；尚不是实际渲染或真机验证。
- 新增外置贴图导出工具 `externalize_gltf.py`，为八套人物和游戏办公楼生成 glTF + BIN + 共用图片衍生资产。保留每个非图像数据视图的原字节，重新对齐并映射 accessor 索引；骨骼、动作、节点、材质、网格及场景设置继续追踪原 GLB。原始文件不变。
- 暂存衍生资产包含 9 个模型、108 个图像引用、52 份独立 PNG；原嵌入图像合计 102,225,082 bytes，共享图片合计 48,899,317 bytes，几何/动作 BIN 合计 16,392,608 bytes。它们位于忽略提交的 `.platform-staging/external-textures/`；报告 `artifacts/gltf-external-texture-assets.json`。这是源衍生结构盘点，不是 Cocos 最终包体下降结果。
- 衍生工具的真实程序员模型测试核对 53 骨、8 动作、各视图原始字节、accessor 映射、图片原字节与重复导出的确定性，错误 GLB 被拒绝。完整回归现为 62 项通过；`npm run check` 覆盖 Node 和全部 Python 工具语法，退出 0。

下一步把衍生资产按稳定 UUID、材质采样与源指纹接入 Cocos，再核验实际共享图片依赖、骨骼/动画导入和渲染。当前 Cocos 仍使用原 GLB，不能把暂存衍生模型写成已接入，也不能把源图像共享比例当作实际包体节约。
