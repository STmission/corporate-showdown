# 08 · 开发状态与首关原型

制作参考：2026-10-02 起统一采用 [Riot 公开实践参考与本项目基线](11-riot-production-baseline.md)。本文件已有规则和数值按该基线评审；未验证的条目仍为设计目标。
版本 v0.3 · 2026-10-01 · 立项已确认，G1 进行中

## 1. 已确认的项目方向

用户已确认立项并授权开始开发。核心目标为准点下班，保留 3D 建模、场景通关、NPC/BOSS战斗、多人联机、微信小游戏与 iOS App 目标。

立项确认不等于所有原型数值、引擎选择或收费商品均已冻结。先制作首关，依据试玩验证调整，再推进正式双端工程。

## 2. 本轮实现

- 原创几何白模办公室：工位、打印机、门禁柜、电梯、植物与道具。
- 两种职业：研发干扰脉冲、行政范围冲撞技能；基础移动、三段攻击、闪避、拾取、投掷。
- 五类道具：键盘、转椅、咖啡、灭火器、纸箱护盾。
- 两项连续互动交接，组长两阶段战斗，召援、攻击预警及限额会议扣时。
- 免费闪退侠变身：短时强化攻击与护盾。
- 单人及最多四人服务器房间，准备/开局、房间码、同服务联机、60 秒重连保留期。
- 服务器权威移动、伤害、计时、任务与结算；倒地、救援、单人一次自救、个人与团队撤离结果。
- 浏览器键盘及虚拟摇杆/触控按钮，原创合成音效开关。

结果仅保存在内存，没有持久化账号、货币或商品权益。正式单人/多人原型统一在线服务器处理；没有与正式离线模式混用。

## 3. 运行与操作

在项目目录执行：

```sh
npm ci
npm start
```

浏览器访问 `http://127.0.0.1:4173`。默认仅监听本机，服务不会被直接开放到公网。

第一人称操作：鼠标环视，WASD/方向键前后移动与侧移；左键/J普攻；K职业技能；空格闪避；E长按交接/拾取/救援/撤离；L投掷手持道具；Q变身；ESC/右上角菜单继续或退出返回大厅。场景标明打印角、门禁柜和电梯。

同机多标签页可用房间码合作。要在受信任局域网内用其他设备测试，执行 `HOST=0.0.0.0 npm start`，其他设备访问服务器电脑的局域网 IP 与相同端口。HTTP局域网不适合作为生产发布，也未完成真机联机验收。

## 4. ADR-001：独立浏览器玩法原型

本机检查发现 Node、.NET、Cocos 与微信开发者工具，没有发现 Unity/团结引擎编辑器。本轮采用 Three.js 3D 渲染、Node/ws 权威服务、纯 JavaScript 领域逻辑，尽快形成可试玩且可测的玩法闭环。

这是玩法验证的独立原型，不替代正式引擎决策。04 技术文档中的 C# / Unity/团结引擎方案仍处于预研；浏览器源码不被宣称为可直接提交微信或 App Store 的工程。

进入正式工程时复用已验证的规则、关卡参数、测试用例与模块边界；原型程序化白模需按美术标准替换/导出到选定工具链。引擎兼容性、许可证、SDK版本和双端真机性能必须在 G1 另行验证。

## 5. 验证记录

执行 `npm test` 验证关键规则和真实 WebSocket 服务；`npm run check` 检查 JavaScript语法。测试覆盖：准备门槛、计时/扣时、非法输入、碰撞、出口锁、共享交接、重复拾取、掉线、救援、幂等结果、BOSS触发、单人/双人自然通关路线、四人房间与重连。

浏览器验证使用 browser-use：大厅、简报、场景渲染、键盘移动/攻击与计时显示。界面截图在本地 `artifacts/`，不作为正式美术或真机测试结果。

可运行 `browser-use < prototype/tools/browser-smoke.py` 做第一人称进入、移动、环视、菜单、返回与再次进入测试。完整单人/双人通关路线由规则层自动化测试覆盖；不能将其写成浏览器完整通关验证。需先启动本地服务及可连接浏览器。

## 6. 本阶段已知差距

尚未完成微信小游戏导出、iOS构建/签名、真机性能、跨端账号、线上鉴权、持久化存档、真实支付、运维部署、全五关、正式3D美术/骨骼动画和竞技对打。原型接口只适合本地受控验证，不适合直接公网运营。

本切片简化了行政技能的推车运动表现、BOSS招式组合、道具投掷模型、技能免控细节与导航；缺少首关可选救援NPC支线。UI 支持窄屏，但还未通过正式设备矩阵测试。

## 7. 下一里程碑

G1：定版正式引擎与版本；完成微信/iOS同一灰模场景；核验网络、资源、触控与最低机型；记录真实测量数据。

G2：按试玩结果调整首关节奏与战斗；补充可选支线、招式、道具表现和正式资产；再开展四人弱网与平台真机回归。
