# 17 · ADR-005：事件确认与操作幂等

v0.4.1 · 2026-10-03 · 原型实现与本地联机验证；M2 仍未整体验收。负责人及评审人待团队分配。

遵循 11 文档的项目制作基线，参考 Riot 公开实践，不代表其内部规范。

## 问题和决定

原快照仅保留最近 30 条事件，断线或客户端停顿后可能遗漏任务、危险及结果反馈。重连还会重置客户端事件位置，产生重复反馈。准备、换装和出发请求缺少稳定回执，回执丢失后的重发无法区分旧操作和新意图。

将高频输入、可恢复状态快照、事件确认、低频操作回执分开处理。移动仍使用 16 文档的模拟确认和预测；HP、任务、库存及通关仍由服务端裁决。客户端事件消费仅展示反馈，不执行权威任务或奖励。

协议升级为 `protocolVersion=2`、规则版本 `rules-0.4.1`。旧协议必须刷新客户端；准备/换装/出发还必须提供 `requestId` 和 `commandSequence`，测试工具同步修改。办公楼和人物资产未改变，不为本轮虚增美术版本。

## 按玩家确认的事件补发

房间保留最近 2,048 条事件日志，另保留原来的最近 30 条窗口供模拟检查使用。各会话记录确认位置 `eventAck` 和已发送上界 `eventSent`。个性化快照最多提供 64 条未确认事件，附带 `eventBase`、`eventHead`、服务端确认位置和 `eventGap`。

客户端按连续事件 ID 消费，仅推进已处理位置；重复快照与重连补发不重复消费。客户端通过独立确认消息及输入消息携带确认位置；服务器只接受单调、整数且不超过已发送上界的确认。恢复连接时先核对保留令牌，再接受该玩家已处理的位置并生成补发快照。即使行动已结束、不再发送输入，快照中未确认的位置仍会触发再次确认，避免回执丢失后卡在第一批历史消息。

日志达到上限会淘汰最老记录。当玩家落后于保留范围时，服务端明确标记缺口，客户端提示历史反馈过期并从当前权威状态继续同步；不会把被淘汰的反馈宣称为已补发。旧音效和技能环不会在重连时集中播放，但事件位置仍会确认。不是无限历史日志，也不是跨服务器重启的持久化事件总线。

## 低频操作回执

本轮覆盖准备、换装、出发三种会改变房间状态的操作。客户端最多排队 32 项，串行发送，每秒重发队首同一意图，收到匹配回执后发送下一项；断线暂停，恢复后保留尚未确认的请求。新房间清空队列与序号。

每个会话的 `CommandLedger` 保存最后处理序号及最近 128 个回执。序号从零开始连续推进；成功和规则拒绝都会生成固定结果并消费该序号。重复序号及相同请求返回原回执，不再次执行操作；同一编号改变参数会报冲突；跳号会报顺序错误；被淘汰的旧序号会报过期，不会重新执行。用于传输的事件确认位置及协议版本不属于操作参数，重发时新的事件确认不会被误判为改变意图。

实际 WebSocket 测试覆盖出发后重复同一出发请求，以及断线重连后重放已成功的换装请求；两者返回原成功结果，没有重复出发或改变战斗中的装扮。执行路径仍校验身份、房主权限、装扮合法性和资源准备版本。

创建/加入的匿名请求尚未接入跨连接幂等恢复；大厅断线仍采用删除成员及失效令牌的原型规则。主动离开重复执行没有二次游戏效果，但不在本轮三种操作回执范围。正式账户、商品订单、奖励、交易回执及服务器重启恢复仍属 M5，不能由此声明支付幂等已完成。

## 验证与证据

`npm run check` 通过；完整 `npm test` 49 项通过。修正恢复时的确认消息后，再针对相关网络和可靠通道用例验证。

新增单元及集成测试覆盖成功/失败回执重放、变更参数、跳号、过期回执、队列顺序、断线暂停、最新 30 条窗口以外的事件恢复、重复事件消费、伪造未来确认拒绝及日志缺口。

真实本地 WebSocket 关闭后等待约 30 秒再恢复：身份和操作序号保留；模拟时间继续推进；未确认事件恢复，已消费事件不重复；确认之后事件从待发送集合移除。本地报告为 `artifacts/network-long-reconnect.json`，最后一次测试会刷新记录。100/200 ms 消息延迟试验继续通过，报告为 `artifacts/network-delay-report.json`。

上述证据是实际本地服务和 WebSocket，不是原生微信/iOS 客户端。业务消息延迟不是 TCP 层丢包整形。浏览器渲染操作复查仍未完成；之前浏览器控制超时不能写成通过。仍需验证底层丢包、完整后台生命周期、容量、CI、持久化和正式双端工程，M0—M6 长期目标保持不变。
