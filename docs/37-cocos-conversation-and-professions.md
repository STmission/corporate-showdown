# 37 · Cocos 职业人物与交谈接入

2026-10-05 · 根工程 0.6.6 · Cocos 0.3.2

## 理由、范围与兼容

网页已有医生、教师独立服装与交流动作，但引擎仍沿用旧人物库。本轮把两套职业资产和面对面交流接入 Cocos。办公层布局、性别／职务切换、服务端战斗与剧情规则保持兼容；当前产品仍是单人剧情原型。按公开 Riot 工程参考制作，不代表其内部规范或认证。

## 已实现

- Cocos 导入完整办公层、原八套人物和女医生／女教师，共 11 个模型、54 张共享来源图像。医生白大褂／听诊器与教师浅色上装／深绿裙装／眼镜沿用独立 Blender 源资产，不使用商业游戏提取模型。
- 十套人物各增加一个 4 秒、53 骨骼旋转通道的 Talk 循环：医生安抚、教师与销售讲解、其他人物倾听。按目标静止姿势重定向，原网格、权重、八个动作、原始二进制视图保留；总人物动作数为 90。源 GLB 与 Blender 文件不改写。
- NPC 服装按共享职业选择器加载；交流时临时面对面镜头、右侧中文对白、隐藏移动／攻击操作。Esc、结束、服务器释放、断线、倒地与退出统一恢复原第一／第三人称及原朝向。
- 修复 Cocos 教师镜片导入后透明度未传到标准材质的问题，仅修改实例的 mainColor alpha；实际值为 20/255。其他玻璃外观仍需另行校正。
- 单人出发先准备所需人物和声音，再创建房间；准备状态禁用重复出发并显示中文提示，避免资源准备期间消耗房间重连保留时间。

导出流程在外置 glTF 阶段附加 Talk，记录动作库／工具指纹。实际导入后显式迁移资产合同，只追加新人物和 Talk；原 UUID、预制体、网格、骨骼与八动作标识保持不变。审计同时检查共享图像来源、职业网格数、BLEND 深度写入与 MASK 状态。九个独立办公模块保持可用，但本轮 Cocos 仍加载完整办公层，尚未实现模块流式加载。

## 已验证

- `npm run check`、96 项完整回归和 Cocos 严格 TypeScript 检查通过。新增检查实际十套派生文件的旧几何／动作／数据视图以及新动作对独立重定向结果的数值误差，不只检查文件名。
- Cocos Creator 3.8.8 的 Web 与微信构建完成，退出码 36 经构建日志与导入／优化门禁确认成功；11 模型／54 图像合同通过，构建源码指纹与当前文件无漂移。
- 实际 Web／微信编译产物验证八项输入、交流恢复、职业选择与 Talk 优先级通过。
- 浏览器实际进入场景，教师新服装与镜片、Talk 手势、中文日程线索、Esc／结束、第一与第三人称恢复、退出回大厅已验证。证据为 `artifacts/cocos-conversation-runtime-032.json` 与 `cocos-conversation-dialogue-032.png`。

## 首次进入复查

前次新页面首次准备人物期间发生重连保留超时并返回大厅，第二次进入成功。上述预加载调整后，最终新页面只点击一次出发即进入 running、7 人物，随后教师 Talk／面对面镜头成功。结果记在 `artifacts/cocos-conversation-preload-032.json` 和两张同前缀截图。复查有明显准备等待与主线程停顿；截图采样间隔不能当成准确加载时长，本轮仅确认首次进入成功，未作性能验收。

## 未完成与限制

真人近景品质、面部表情／口型、完整职业衣服与角色、持枪手部动作、剧情全流程和最终音效听感仍未完成。场景玻璃视觉存在差距；导入器提示不支持部分 specular／emissive 扩展，尚未完成材质等价验收。首次加载明显等待，尚无设备加载时间／内存达标结论。当前实测为桌面浏览器，Cocos 移动对白布局与滚动、微信真机、iOS 新构建／签名与商店发行均未验收。
