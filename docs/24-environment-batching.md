# 24 · 办公楼静态合批

版本 v0.1 · 2026-10-04 · 实际构建与运行结果见下方；负责人/评审人待分配

## 问题与设计边界

23 文档确认办公楼包含 6,300 个网格节点，浏览器绘制调用偏多。本轮仅改变 Cocos 场景表现，原始 Blender、GLB、衍生 glTF、空间布局、服务器碰撞与协议保持不变。角色、任务、道具和危险标记不参与环境合批。

`EnvironmentBatching.ts` 对不透明静态网格按同一实际材质、同一世界线性变换基底、8 m × 8 m 空间格和渲染属性分组；每批最多 64 个来源，最多 60,000 顶点/索引。透明材质保留原有排序粒度；动态、形变、烘焙贴图/光照探针物体跳过。单例保留原渲染器，避免整层合成一个物体而丢失剔除粒度。

读取本机 Cocos 3.8.8 `cocos/3d/assets/mesh.ts` 和 `cocos/3d/misc/batch-utils.ts`：Mesh.merge 会旋转法线，但没有变换切线。因此仅在相同线性基底中烘焙平移，目标节点保留来源的旋转/缩放，避免非均匀缩放和法线贴图变形。目标 TRS 重建也检查矩阵偏差。

合并结果在隐藏原物体前逐项检查所有顶点属性与每个三角形索引；位置误差上限 0.0001，其余属性误差上限 0.000001。发现不一致就销毁候选并保留原模型。源节点不重挂，不自动改变碰撞；退出/销毁时恢复原渲染器并释放生成网格。

## 验证方法与限制

Web QA 参数 `batch=off` 用于同视角对照；`profile=on` 启用引擎性能覆盖层及只读 DOM 性能记录，普通入口隐藏该层。DOM 的 `data-batching` 记录来源/结果数量、合批数、失败数、已核验顶点、误差和处理耗时。构建指纹新增工具源码，不把浏览器结果当真机。

首次实际运行没有减少渲染器，证据 `artifacts/cocos-batching-initial-runtime.json`。增加统计后，实际确认 6,300 个来源全部被错误判断为透明：标准材质的 forward-add / planar-shadow 通道含混合状态，不能用“任意通道混合”判断物体透明。现改为标准效果 opaque technique 和主通道检查，并在首次 update 执行；此前定时回调的短时间观察不足以单独证明生命周期故障。严格 TypeScript 检查通过；根语法检查与 62 项回归通过，回归日志 `artifacts/cocos-batching-regression.log`。这些规则测试不能替代实际引擎几何和画面复查。

该方案会在加载时生成额外网格，保留原网格以便回退；可能增加启动耗时和缓冲区内存。它不减少资源下载/贴图显存，也不代替离线合批、LOD、Bundle、设备帧时间和内存门禁。后续需按实际性能数据决定哪些家具适合批处理，以及是否转为可追踪的离线衍生资产。

## 本轮实际复查

主通道修正后的实际浏览器报告：6,300 → 2,552 个环境渲染器，864 批合并 4,612 个来源；跳过 85 个透明来源，失败 0。逐属性/索引检查覆盖 781,331 个顶点，最大局部位置误差 0.0000601477；处理耗时 1,554 ms。原有可见玻璃、家具和空间仍显示。

同一 1280×720 大厅视角，绘制调用 2,108 → 856，减少约 59.4%；可见三角形 322,567 → 336,523，增加约 4.3%，反映空间合批剔除粒度变粗。GPU 缓冲区指标 28.2 → 67.85 MiB，贴图约 161.67 MiB 保持；生成网格内存代价明显。基线/结果的瞬时 FPS 约 16/17，机器同时运行其他项目，不能证明帧率预算通过或稳定提升。

实际单人出发后 NPC 显示与攻击、菜单和退出可用。一次短 W 按键未改变权威 z（仍 5.8），不计为本版移动验证；完整通关与多引擎客户端仍待验证。证据：`artifacts/cocos-batching-baseline-runtime.json`、`cocos-batching-verified-runtime.json`、`cocos-batching-mission-runtime.json` 与 `cocos-batching-lobby.png`。本轮引擎源码修改后的微信/iOS 构建仍需重新执行，先前成功包不覆盖这些修改。

下一轮对比 GPU 实例化与离线衍生合批，优先控制新增缓冲区和启动开销；保留 Web `batch=off` 对照和几何门禁，不以减少 draw call 代替完整性能验收。
