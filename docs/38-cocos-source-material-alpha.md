# 38 · Cocos 源材质透明度修复

2026-10-05 · 根工程 0.6.6 · Cocos 0.3.3

## 体验问题与改动理由

玻璃会谈室需要能看见里面的人物与设施。实际 Cocos 导入材质已经开启 BLEND、关闭深度写入，但办公层 Material_6 的 baseColorFactor alpha 0.13 没有写入标准材质；结果玻璃看起来像蓝色实体墙。上一轮仅对教师镜片做了单点恢复，本轮改为源资产驱动的透明度修复。

没有改变已确认的办公楼布局、碰撞、导航、武器规则、剧情或人物属性。原 Blender／GLB 不改写，仍保留独立资产与来源；源模型、八原动作与 Talk 派生检查继续通过。当前产品方向仍为单人剧情原型，旧合作底层保持兼容。

## 实现

`sync_assets.py` 从实际外置 glTF 的 BLEND 材质读取非默认 baseColorFactor alpha，生成 `SourceMaterialAlpha.ts`。只收录需要恢复的源因子，不把 OPAQUE／MASK 统一改成透明；11 个模型的规则完整核对原始 GLB。

`EngineMaterialAlpha.ts` 在环境实例化、角色实例化时应用规则。核对标准材质、混合状态与深度写入状态后，复制本场景材质，保留原 RGB、纹理、粗糙度、金属度、采样与渲染状态，仅恢复 mainColor alpha。相同源材质共享一个本地副本，退出组件时销毁，不逐玻璃创建 85 份材质，也不修改导入资源。出现不兼容状态会记录 failed，实际实测该数组为空。

Cocos Color 按 8 位量化：办公玻璃源 0.129999995，应用 33/255≈0.129412；教师镜片源 0.079999998，应用 20/255≈0.078431。偏差均不超过半个 8 位阶梯。办公层有 8 个玻璃网格定义、85 个节点引用；现场应用 85 个环境渲染器，教师加载后累计 87 个，两个共享材质副本。

## 已验证

- `npm run check`、97 项完整回归、Cocos 严格 TypeScript 检查通过。新增来源检查对全部 11 个实际 GLB 的透明因子做独立比对；原十套派生网格、骨骼、原动作和 Talk 数值检查继续通过。
- Web 与微信构建成功（编辑器退出 36，经日志与导入／优化门禁确认），实际导入合同为 11 模型／54 共享图像，源码指纹无漂移。实际 Web／微信编译输入、交流与职业选择检查通过。
- 实际浏览器显示玻璃后方家具与人物，单次出发进入 running、7 人物；第一人称环视、教师镜片透明度和退出回大厅／清空人物通过。
- 原实例化仍启用 5,898 个渲染器、61 个网格组、26 个材质组；透明的 85 个渲染器继续排除，失败为 0。这里是批处理资格与状态证据，不是 GPU draw call 或设备帧率达标声明。

证据：`artifacts/cocos-material-alpha-033.png`、`cocos-material-alpha-runtime-033.json`、`cocos-material-alpha-runtime-verification.json`；检查日志同 `cocos-material-alpha-` 前缀。两端构建与编译产物检查均已完成；微信设备运行仍未验证。

## 未完成

透明修复不等于真实玻璃的折射、镜面反射与材质等价验收；导入器不支持的 specular／emissive 扩展仍需处理。当前引擎窗外仍是灰色背景，完整海岸／天空表现待接入。人物近景、衣服褶皱、表情口型、其他职业、握持动作与剧情全流程尚未完成；首次加载、微信真机、iOS 本轮构建／签名、设备预算与发行仍未验收。

本记录更新 37 文档的玻璃透明度缺陷状态；旧阶段的截图与限制保留可追踪。M0—M6 总目标继续执行。

后续状态：Cocos 0.3.4 已接入原创晴天天空并验证海岸可见，替代本阶段灰色天空缺失状态；真实反射／动态水面与最终材质仍未完成，见 [39 文档](39-cocos-coastal-sky.md)。
