# 21 · Cocos 权威联机客户端切片

版本 0.2.0 · 2026-10-04 · 实现与构建推进中，尚未完成实际引擎首关验收

## 原因与兼容影响

20 文档的资源导入预研不能完成第一人称合作首关。继续使用 Cocos Creator 3.8.8 试验客户端，接入现有服务器和共享规则，验证正式双端路线；仍未冻结正式引擎。保留海岸总部的房间、工位、茶水间、演讲区、休息区和卫浴空间，不修改布局或服务器玩法。

服务器协议仍为 3，规则 rules-0.5.0，环境 headquarters-v0.8，人物 characters-v0.9。根目录浏览器原型仍是 0.5.1。Cocos 子工程版本 0.2.0 不表示微信或 iOS 已验收。参考项目自行制定的 Riot 公开实践基线，不是 Riot 内部规范。

## 已实现

- `prototype/client/session.mjs` 管理版本握手、房间身份、输入序列、可靠准备/出发、快照、预测纠正、插值、有界事件确认及连接恢复。核心伤害、任务、倒计时和结果仍由服务器裁决。
- Cocos 的 `PlatformProbe.ts` 连接该会话层；包含中文大厅、员工代号/房间码、男女/四职务选择、两种已有技能职责、单人创建及合作创建/加入、资源准备、出发、第一人称移动/环视、动作意图、菜单、主动退出与返回入口。
- 环境使用独立游戏 GLB；八份人物资源已复制并记录源指纹，按本房间服装加载 Prefab，检查八个动作名称。服务器人物与 NPC 状态驱动 SkeletalAnimation。
- `EngineUi.ts` 使用 Cocos UI，包含键鼠及触控意图控件。触控、镜头手感与完整回路尚未真机验收。菜单明确提示在线计时继续。
- `sync:cocos` 从现有 `.mjs` 规则和会话模块生成引擎 `.js`，记录源 SHA-256；构建脚本检查指纹、生成文本、资源及场景引用，防止两套规则静默漂移。
- 服务器提供限定根目录的 `/engine/` 静态资源入口，便于 Web 客户端与现有 WebSocket 同源验证；GET/HEAD、路径边界及响应类型受控。尚不是公网平台服务。

这里的“已实现”指源码存在及范围可检查，不代表全部交互已经实际试玩。

## 检查证据

新增会话集成测试启动真实服务器及四条 WebSocket，验证四种不同男女/职务、全员准备、可靠出发、先预测后权威移动、旧快照拒绝、同身份重新连接、主动离开，以及引擎资源入口越界拒绝。另一用例覆盖资源版本拒绝与已处置连接不自动恢复。完整测试 60 项通过，记录 `artifacts/engine-session-regression.log`。这不是四个 Cocos 客户端的实际多人试玩证据。

Web 构建已在 Cocos 3.8.8 返回成功码 36，记录 `artifacts/cocos-web-desktop-build.json` 与日志。初次构建暴露 `.js` 模块被误判为 CommonJS，已将子工程包声明为 ESM 并清理该工程的生成脚本缓存后重新构建。

实际 Web 启动还暴露编译器将 Map/Set 展开转换成数组 concat，诊断函数读取角色项失败，并会影响服装准备。已改用明确的 `Array.from`，重新构建成功；菜单清理也改为销毁旧 UI 节点。修复后的实际点击、进入首关及渲染复查尚未完成：本轮 Chrome 远程调试授权未能通过，辅助功能权限导致自动点击授权失败。不能把成功构建写成该运行缺陷已获实际复验。

## 复现

在仓库根目录运行 `npm run sync:cocos`，再执行 `npm run build:cocos:web`。启动 `npm start`，访问 `http://127.0.0.1:4173/engine/`。原型入口仍为 `/`，场景设计入口仍为 `/studio`。

TypeScript 使用编辑器附带编译器和 `platform/cocos/tsconfig.json` 检查。`skipLibCheck` 仅跳过供应商声明。根工程运行 `npm run check` 和 `npm test`。微信与 iOS 的真实平台门禁继续按 20 文档记录。
