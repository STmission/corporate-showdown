# 14 · 男女与职务装扮联机选择

2026-10-02 · v0.3.1 · M1 角色接入。

## 已实现的行为

大厅和合作房间可选择男生/女生，以及程序员格子衬衫、电商商务穿搭、销售西装、明星潮流穿搭。房间展示选择名称，并以待机模型提供角色预览；进入行动后隐藏本人的世界模型，显示对应职务的袖口。程序员使用格子袖口，其余服装使用职务配色。第一人称手臂仍为原程序化资产，尚未做正式手臂绑定与服装网格替换。

性别与职务装扮独立于现有研发/行政战斗职责。八套外观共享移动、血量、技能判定和 1.68 米镜头眼高；性别或服装不改变数值。四种职务的独立战斗技能仍是后续玩法任务。

服务器仅接受 `male/female` 与 `programmer/ecommerce/sales/celebrity` 枚举，不能以客户端传入路径任意加载资源。非法创建参数在建立房间前拒绝。选择写入权威快照，已有成员恢复连接后继续使用相同选择。

## 准备和变更协议

房间新增 `loadoutRevision`，快照包含 `assetVersion`。玩家入房、离开准备房间或实际改变外观时增加修订，清除全员准备状态。重复提交相同外观不清除准备；行动中不能换装。

客户端加载本房间所有选择的模型后提交 `ready=true`，包含 `assetRevision` 与 `assetVersion`。服务器拒绝过期修订或不匹配的场景资源版本，开始时再次检查每位成员的准备修订。该确认是客户端就绪与版本协议，不是对客户端下载内容的密码学证明。

网络消息扩展：创建/加入包含 `gender/job`（缺省为男程序员）；`appearance` 仅用于准备房间换装；`ready` 包含两个资源版本字段。旧页面应刷新，否则准备请求会被拒绝。完整传输协议版本、可靠事件与预测纠正仍留待 M2。

## 资源与失败处理

首屏加载办公楼和两个 NPC 共用模板，其他服装按实际房间需求加载，缓存与合并同一资源的并发请求。骨骼实例复用几何与贴图；换装销毁旧实例的动画状态，保留缓存资源供再次进入。

加载中禁用准备和出发。失败保留错误提示，提供“重新加载服装”，避免跟随每次服务器快照不断重试。房间修订变化后旧异步加载结果不能替新修订提交准备。

## 验证范围

`npm test`：33 项规则/资产/真实服务器用例。新增覆盖八种外观数值一致、非法参数不更改房间、修订变更清除准备、过期资源拒绝、重复外观不清除准备、行动中禁止换装、快照及真实服务器恢复选择。

浏览器验证已通过：8 套模型可见、换装清除准备、重新准备进入游戏、女生程序员的第一人称装扮一致、页面异常为 0。截图位于 `artifacts/wardrobe-room-preview.png` 与 `artifacts/wardrobe-first-person.png`。

`prototype/tools/appearance-smoke.py` 通过实际浏览器的选择控件 change 事件、按钮处理与房间传输逐套检查模型显示、换装重新准备、第一人称袖口和页面异常。该脚本对本项目 DOM 触发 UI 事件；物理鼠标/键盘进入退出另由 `browser-smoke.py` 检查，不将两种范围混为人工全面试玩。

微信/iOS 真机、内存预算、服装 LOD、正式动作和四职业技能尚未验收。
