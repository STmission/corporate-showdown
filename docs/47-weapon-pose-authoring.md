# 47 · 独立枪械持握与射击动作制作

2026-10-06 · 独立美术制作阶段，根工程 0.6.12／Cocos 0.3.10 未变更

## 问题和制作方向

46 文档的真实手骨挂点解决了武器随手臂移动，但中性携带动作不能满足第三人称射击观感。本轮使用 Blender 制作独立手枪／步枪 Hold、Shot 动作样板，并保留原人物、动作和游戏裁决。原有办公层空间未变更。

源文件 assets/animations/weapon-poses-v1/weapon-pose-pilot.blend，独立骨骼动画库 workplace-weapon-poses.glb。脚本 blender/build_weapon_pose_pilot.py 从 grounded-v1 男程序员读取，双臂两节 IK 离线求解并烘焙为现有 53 骨骼的变换；手枪／步枪使用现有共享武器部件和 weaponGrip 握持点作为渲染参照。Hold 2 秒，Shot 0.5 秒，射击有后移／抬高／恢复轨迹；不是动作捕捉，也不是运行时 IK。

烘焙使用 Bone.convert_local_to_pose 明确处理父链，逐帧核对全部骨骼的位置误差，超过 0.5 毫米拒绝。源文件 SHA256 验证原资产未被覆盖。验证脚本重开 Blender，渲染实际网格，再真实导入导出的 GLB，核对四动作的手腕、头部和脚部位置；误差大于 2 毫米拒绝。导出初始帧另以 Three.js 独立读取 GLB 变换并套用共享握持点，检查枪管沿人物 +Z、枪械上方沿 +Y。这不能替代游戏射线与动画枪口一致性检查。

## 制作状态

首次渲染发现预览材质未设置节点基础色，修正后重新导出；近景发现手臂／躯干接触不理想，前移持握目标。右肘极向角曾使手臂折向躯干，结合实际肘位置和近景图调整双臂极向角为 -π/2，最终双臂网格可见。

最终四动作全帧烘焙位置最大误差 0.000000899 米，手腕目标误差最大 0.001883 米；53 骨骼 GLB 真正重导入后，四动作各四姿势的手／头／脚位置最大误差 0.000000728 米。源重开、两张实际网格渲染和初始帧枪械方向检查通过；见 assets/animations/weapon-poses-v1/validation.json、artifacts/weapon-pose-exported-axes.json、weapon-pose-pilot-build.log／validation.log。validation.json 记录验证所用资产哈希；manifest.json 为生成阶段记录，验证状态以关联 validation.json 为准。

视觉复查：双臂已置于身体前方，步枪左手位于前部下方；手指仍平展，枪托／手指接触不准确，武器及人物精度仍未达到目标品质。通过位置与方向验证不等于通过最终美术验收。

本轮根工程语法检查与 109 项回归通过，记录 artifacts/weapon-pose-source-check.log、weapon-pose-regression.log。独立美术脚本额外执行 Python 编译检查。游戏代码和正式平台资源未接入新动作，所以没有为本轮重复声明新的平台构建或真机验收。
