# 18 · 角色动作制作与接入

游戏 v0.5.0 / 角色 characters-v0.9 · 2026-10-03 · 动作片段与原型接入已实施，M1/M4 美术验收未整体完成。负责人、评审人待团队分配。

依据 11 文档的项目制作基线，参考 Riot 公开实践，不代表其内部规范或资产品质认证。

## 问题与制作决定

原八套角色只有轻微呼吸待机，游戏在渲染时临时旋转四根骨骼模拟走路和攻击，倒地通过整个角色侧转代替。它不能作为可编辑、可导出的动作库，也不适合逐动作检查。

继续编辑现有 `assets/characters/workplace-characters.blend`，保留原创东亚造型、男女四职务服装、贴图和 53 根骨骼，增加八个动作：Idle、Walk、Run、Attack、Hit、Down、Rescue、Cast。每套独立 GLB 含对应的八个命名片段，共 64 个片段；原生源文件包含可继续编辑的 Action/NLA 轨道。

这些是本项目创作的关键帧动作基础版，没有使用演员扫描或动作捕捉，不宣称已经完成电影级或最终商业动画。它替代原游戏临时摆动，不改变人物模型质量或服务器战斗数值。

## 源和导出流程

`blender/animate_characters.py` 打开现有源工程，生成关键帧与 NLA 轨道，按骨骼世界方向编制摆腿、屈膝、脚部补偿、上身与手臂动作。动作原地播放，逻辑控制水平移动；根骨可做垂直起伏和倒地旋转，不提供客户端水平 Root Motion。

首次真实渲染发现救援姿势双脚悬空、膝弯方向不合适，随后改正小腿弯曲、脚部补偿和蹲身高度，重新导出。GLB 检查进一步验证救援踝部接近地面，避免只凭文件有动画就判定可用。倒地预览展示落地过程中的中间姿势，完整片段结束后身体降低。

导出先进入 `.animation-staging`，八份完成后再替换公共 GLB 与源文件；失败的部分导出不会直接覆盖公共库。多文件替换不是事务式发行资源更新，正式客户端仍需带内容指纹的资源发布与回退机制。

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --python blender/animate_characters.py
npm run check
npm test
npm run audit:assets
```

脚本会重新编制这些动作，后续手工精修曲线后不要直接重跑覆盖；应在源工程继续编辑，或将改动回写脚本。旧 `build_characters.py` 是人体与衣服的初始生成流程，不能替代当前精修源文件。`normalize_glb.py` 新增保留本角色动作的选项；其批量入口保留所有本角色片段，同时修正皮肤/衣服不透明与头发透明裁切。

`assets/characters/manifest.json`、`blender/animation-report.json` 与 `assets/asset-audit.json` 记录版本、动作、字节数与指纹。实际 Blender 3D 渲染为 `assets/renders/character-actions-v09.png`，不是 AI 概念图。图中从左至右按库排序展示女性明星待机、女性电商行走、女性程序员跑步、女性销售攻击、男性明星受击、男性电商倒地过程、男性程序员救援、男性销售施法准备。

## 游戏中的动作状态

`shared/animation.mjs` 管理动作合同和优先级；`public/character-animation.mjs` 使用 Three.js AnimationMixer 播放原生片段、短暂交叉淡化，并停止退出的动作，避免所有旧片段继续计算。

大厅待机；移动根据实际位移速度选择 Walk/Run 并调整片段速度。受击根据权威 HP 下降触发，不把救援后无敌时间误当受击。攻击依据权威 `attackUntil` 切换，NPC 施法准备依据 `cast`；救援依据交互目标确为倒地队友；倒地/淘汰使用 Down 并保持末帧。原来的四骨骼摆动与整身侧转已移除。

动画仅改变表现，命中、冷却、移动、血量、救援和结算仍由服务器裁决，不靠客户端动画回调产生伤害。第一人称袖口/手臂仍使用原程序化模型；本轮接入的是第三人称世界模型和 NPC。

服务器和准备消息新增独立 `characterVersion`，握手与快照也携带此版本。客户端要求八个动作全部存在，缺失则保持资源未就绪；服务器拒绝过期人物版本。协议升级为 3 / rules-0.5.0，旧页面必须刷新。办公楼维持 headquarters-v0.8，不把角色修改误写为场景布局变更。

## 验证与真实限制

`npm run check` 和 Python 语法检查通过；完整 `npm test` 51 项通过。新增测试不只检查动画名称，还解码实际 GLB 数值轨道、构造节点层级并运行 Three.js 混合器：

- 八套模型均保留 53 骨骼、八个对应片段和正确透明模式。
- 时间递增、轨道有限、旋转四元数归一；循环片段首尾位置/缩放一致及旋转连续。
- 行走实际改变腿骨，倒地降低头部，回到待机能恢复站立。
- 水平根位置固定，救援双踝接近地面。
- 状态优先级使用权威数据；人物资源版本过期不可准备。

在完整回归后补强循环接缝与踝部断言，对相关两项动画测试再次验证通过。八套关键帧导出和修正后的真实渲染均完成。浏览器动作切换的实际操作复查尚未完成，不能把离线混合器测试写成完整网页或手机视觉验收。

仍待制作三段普攻、闪避、持物/投掷、交接、撤离、变身、完整技能及第一人称绑定手臂。当前完整身体受击/攻击切换可能产生脚滑或暂停步态，尚无上下身分层与脚部 IK；女装裙摆、手指握持、头发/服装穿插和动作过渡需要逐帧精修。NPC 死亡目前移除实体，不等于已完成死亡演出。

移动设备动画开销、真实帧率、四人密集战斗可读性、微信/iOS 真机构建仍未验收。该阶段没有关闭 M1、M4 或完整 M0—M6 目标。
