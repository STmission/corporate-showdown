# 32 · 海岸总部模块场景

2026-10-05 · 原布局 headquarters-v0.8 保留；模块库 environment-modules-v0.1

## 制作目的与兼容

用户要求场景模块化。本轮从已批准的 `assets/models/coastal-headquarters.blend` 提取九个区域：办公区、中央休息区、演讲区、茶水间、服务核心、猫区与休憩、会议室、建筑壳体和海岸环境。保留原完整 Blender 工程、完整展示 GLB 和默认游戏 GLB，没有重建或挪动办公层。新增网页选项 `/?environment=modules` 用九个模块加载同一层；默认与 Cocos 客户端继续使用原完整环境，Cocos 分包尚未接入。

## 资产规则

每个模块有独立 `.blend` 和内嵌纹理的 `.glb`，均为米制；Blender +Z 朝上，GLB +Y 朝上。清单 placement 是 GLB 三维世界重组坐标：模块本地原点放回该坐标即可重组。工作模块的枢轴是已登记的功能区域锚点，建筑和海岸使用楼层世界原点。原始对象的世界变换在提取时转换为模块本地变换，不依赖原场景父物件。原始网格 ID、区域集合、源工程／脚本／导出指纹与重组坐标写入 manifest。

原区域集合提供主要分区；原生追加细节按位置分配，导航修正墙体纳入茶水间。所有 6,300 个环境网格只分配一次，排除展示人物、灯光和摄像机。106 个原始墙面标记与六个共享隔墙别名共同保留 112 个逻辑墙体追踪；运行时仍读取共享的原楼层碰撞，模块清单不是独立生成的战斗碰撞或导航数据。

脚本先写 staging。独立验证与实际查看通过后才能推广为 v0.1，不把输出生成当作可用证明。提取发现 Blender 多场景导出会带入原场景仍被选中的一块墙体，已设置 use_active_scene，验证同时检查无额外场景、对象重复或遗漏。

## 验证方法与限制

实际加载九份保存的 Blender 场景，核对米制、源 ID、网格数、三角形和加回枢轴后的包围盒。随后实际导入九份 GLB 重组，逐原始网格对照双向顶点最近距离（小于 0.3mm）、三角形数、世界表面积及全部源 ID；源完整工程 SHA256 保持一致。重组预览使用实际 GLB，天花板仅在剖视渲染中隐藏，仍参与几何检查。

GLB 支持的 PBR 材质与纹理会保留，但 Blender 原生程序节点并非全部可在 GLB 中表达。验证不证明完整 Blender 着色效果一致，也不证明最终美术品质。模块仍沿用原办公模型和风格化猫；未新增写实家具或人物。

网页选项按清单放回模块，继承原网格合批逻辑；各 GLB 会重复包含共享材质／纹理，未去重也未测量真机预算。九次加载及批次数不同，不能声称更快或更省内存。Cocos 模块化加载、LOD、流式区域加载、独立物件编辑器和微信/iOS 真机仍未验收。

资产检查已通过：九份源场景加载、九份实际 GLB 导入、6,300 个网格完整重组，822,534 个三角形一致，最大双向顶点偏差约 0.0054mm；实际重组渲染已查看。模块资产回归另外核对唯一源 ID、内嵌纹理、无人物骨骼及 112 个墙体身份（共享隔墙必须坐标、尺寸、高度和材质完全一致）。最新语法检查与完整 85 项回归通过。浏览器实际 `/?environment=modules` 加载九个模块，公开场景状态为 modules-v0.1，当前合批 649（不是性能达标结论）；实际单人进入、手枪拾取、第一／第三人称切换和返回大厅已验证，截图与 DOM 证据保存于 artifacts/environment-modules-browser.png、environment-modules-first-person.png、environment-modules-ui-evidence.json。未做完整剧情通关或真机验收。

复现：先运行 Blender 的 extract_environment_modules.py 与 validate_environment_modules.py，查看 staging/reassembled.png，再推广目录；运行 `node prototype/tools/link-module-collision.mjs assets/environment-modules/v0.1` 补齐经精确核对的墙体别名。此工具只更新清单，不改变模型或碰撞。
