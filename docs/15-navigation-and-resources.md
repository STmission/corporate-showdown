# 15 · ADR-003：办公楼导航与资源拆分

版本 v0.3.2 / 场景 headquarters-v0.8 · 2026-10-03 · 已实施本阶段，M1 继续推进。负责人和评审人待团队分配。

制作依据为 11 文档的项目基线，参考 Riot 公开实践，不代表其内部规范或认证。

## 问题与空间调整

原茶水间南侧整片敞开，工作台与游戏存在不同的碰撞判断，电话房间入口受柜台影响，卫生间隔板阻碍内部访问。继续沿用原 52 工位、海景、中央电梯走廊、东西分区及综合演讲茶水间，不改变已批准房间位置。

茶水间南侧新增连续玻璃分隔，同时保留交流室、洽谈室、电话间入口及主茶水间门洞。茶水间主入口位于 x=29、z=2，宽 1.8 米；电话间门洞中心 x=20.9，宽 1.2 米，绕开旁边厨房柜台。淋浴隔板宽度改为 1.8 米，卫生隔板宽度 2.2 米并向外移动，保持隐私且留出内侧通道。坐标使用游戏 Y-up 的 x/z 米。

这些更改已保存到原生 `.blend` 和两份 GLB。不是只修改服务器阻挡。导出脚本逐一确认 112 段实际墙体的世界边界与共享定义相符，两个 GLB 的测试再从节点变换和网格顶点包围盒独立计算墙体边界。

## 统一数据和兼容

`prototype/shared/headquarters-layout.mjs` 维护墙体、主要家具阻挡、地面高度和安全房间快捷入口。场景工作台、游戏关卡和服务器使用同一规则。旧 `headquarters-collision.mjs` 仅保留兼容导出。当前共有 276 个阻挡矩形，其中 112 段墙体，164 项主要家具足迹。

新增主要阻挡覆盖办公椅、厨房柜台和岛台、冰箱、咖啡区桌椅、会议椅、休憩沙发与吊床、洗手台和马桶。小餐具、植物叶片和其他装饰不自动作为碰撞或掩体。静态椅凳目前不能在游戏中推移；完整动态物理仍未实现。

服务器仍裁决移动、遮挡和战斗。工作台改用相同 0.36 米角色半径，房间快捷入口不会落在桌椅内部。舞台与淋浴台高度用于人物落地表现；平面矩形碰撞不是完整三维物理，不支持以此宣称跳跃、攀爬或动态碰撞完成。

准备消息上报客户端实际 `LEVEL.revision`，客户端遇到不一致快照会离开并提示刷新。修改布局需更新场景版本并重新导出；旧页面需要刷新，进行中的旧房间不能无缝迁移。本项不替代后续完整联机协议版本、确认序号、预测和纠正系统。

## 资源和复现

完整展示文件 `assets/models/coastal-headquarters-complete.glb` 为 66,418,604 字节，保留八名展示人物和八组蒙皮；游戏文件 `coastal-headquarters-gameplay.glb` 为 5,768,892 字节，去除展示人物及其资源，无蒙皮。游戏单独加载实际所选角色与战斗 NPC，避免重复下载展示角色；环境下载体积减少约 91.3%。此比较仅是两个文件大小，不是整款游戏包体或真机内存结论。

保留主工程 `assets/models/coastal-headquarters.blend`，继续编辑现有工程，不从旧 GLB 重建覆盖。步骤：

```sh
npm run export:layout
/Applications/Blender.app/Contents/MacOS/Blender --background --python blender/update_navigation.py
npm run check
npm test
npm run audit:assets
```

脚本从共享布局生成的 `headquarters-collision.json` 修改原生墙体、写入碰撞文本和对象追踪标记，保存工程并导出两个 GLB，再归一化透明材质。`blender/navigation-report.json` 记录墙体核验和字节数。资产指纹报告记录 13 份源和导出资源的 SHA-256。脚本针对当前源工程结构进行修改与校验；未来调整模型拓扑后必须重新核验，不假设任意手工修改会自动同步。

## 验证与限制

`npm run check` 通过；`npm test` 37 项通过。导航使用 0.25 米单元从出生点查找各功能房间、舞台、两侧卫生间各隔间、两侧淋浴内部以及全部工作台快捷入口；验证门洞通行、柜台/冰箱/办公椅阻挡和淋浴地面高度。导出检查验证两份 GLB 所有声明墙体的尺寸与位置，游戏包不存在展示人物蒙皮且低于 10 MB。
